numbinder modules guide
=======================

A module is a single Python file (.py) in the modules\ folder next to
numbinder.pyw.

numbinder loads it at startup and adds it to the button "Type" list, marked with 🧩.

WARNING
-------
Modules run with your account's rights. They can read and change files, start
programs, read the clipboard and send keys. Install only code you trust.


1. INSTALLING A MODULE
----------------------
From the app: Settings -> Modules -> "Install module...".
The first time, a warning window appears. You must accept it before installing.

By hand: copy the .py file into the modules\ folder and restart numbinder.

Then select the module in the button's "Type" field (it starts with 🧩).


2. WRITING A MODULE
-------------------
Copy modules\_template.py, rename it (for example, my_module.py), edit it and
place it in modules\.

Required structure:

    MODULE = {
        "id": "my_module",                                  # unique, no spaces
        "name": {"ru": "My module", "en": "My module"},    # shown in the list
        "description": {"ru": "What the module does.", "en": "What the module does."},   # optional
        "version": "1.0.0",                                 # optional
        "author": "you",                                    # optional
        "hold": True,                                       # optional, see below
    }

    def run(ctx, cfg):
        ...

If the file has no MODULE with an "id", or no run() function, the module is
skipped and the error is written to the log.

"hold": True gives the module a second mode. A short press runs it as usual.
Holding the button (for the "Hold To Action" time) runs it again with
ctx.is_hold = True. Without "hold", the module runs only on a short press.

The "description" in English is shown under the Type field in the button
settings.

PRESET LIST IN THE BUTTON SETTINGS (optional)
A module can ask numbinder to show a list of rows with dropdowns in the
button settings ("+ Add preset" adds a row, ✕ removes it):

    MODULE["rows"] = {
        "title": "Presets",                       # shown above the list
        "hint": "Short explanation.",             # optional
        "columns": [
            {"key": "a", "label": "First",  "choices": ["One", "Two"], "width": 14},
            {"key": "b", "label": "Second", "choices": ["X", "Y"],     "width": 12},
        ],
        "default": [{"a": "One", "b": "X"}],      # rows for a new button
    }

The saved rows reach run() as cfg["ModRows"], a list of dictionaries,
for example [{"a": "One", "b": "X"}, {"a": "Two", "b": "Y"}].
Each button has its own list. modules\eq_effects.py uses this.

Column types ("type" in a column; "choice" when it is missing):
    "choice"   dropdown, one of "choices"          -> a string
    "multi"    several of "choices" at once         -> a list of strings
               (click the field: a checkbox list opens; nothing ticked = [])
    "entry"    the user types any text              -> a string
               ("choices" is not used; "default" is the starting text)
"width" is a hint for the field width; each row is shown as its own card.
"item_label" (optional, next to "title") names the cards: "Preset 1", "Moment 2"...

BACKGROUND WORK (optional)
A module may also define start(ctx). numbinder calls it once, about 1.5 s after
it starts, in a separate thread. Use it for work that must run without a key
press, for example listening to a game. Keep any state in ctx.settings() so it
survives restarts. modules\cs2_music.py (if you have it) is an example.

    def start(ctx):
        if ctx.settings().get("enabled"):
            ...   # start your background thread here


3. HELPERS (ctx)
----------------
    ctx.osd("text")         show a message on screen
    ctx.log("text")         write a line to this run's log
    ctx.settings()          the module's own settings dictionary (saved in config.json)
    ctx.save_settings()     save config.json after changing ctx.settings()
    ctx.is_hold             True when the run was started by holding the button

cfg holds the button's own settings: cfg.get("Type"), cfg.get("Path"),
cfg.get("ProcessName"), and so on.

An exception inside run() does not crash the app. It is written to the log
and shown with ctx.osd().


4. LIBRARIES
------------
A module may import any pip package. These are already installed with numbinder:
pyperclip, psutil, pycaw, pystray, Pillow, comtypes.
For others, run: python -m pip install package_name


5. EXAMPLE
----------
modules\layout_fixer.py is the built-in layout fixer. Use it as a reference.
It uses "hold": True: a short press fixes all text in the field, holding the
button fixes only the selected text.


6. TIPS
-------
- Restart numbinder after changing a module file.
- Files whose names start with "_" are not loaded. That is why _template.py can stay.
- Keep run() short. For long work, start a thread inside it.
